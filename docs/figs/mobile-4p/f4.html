P0 → P4 步进

P0
真机实测：LPDDR 有效带宽 + UFS 4.x 读带宽 + OpenCL 白名单复核 + DeltaNet 算子可用性调研（小模型先例 / CPU fallback 成本）
判定物：带宽数字表（一切账的前提）
P1
代理验机制：Ling3.0-tiny（7.9B/1.3B 激活 MoE，128 专家 top8+1shared，3:1 KDA+MLA，官方 BF16/FP8/INT4）；LFM2.5-8B-A1B 为备选对照
Q4_K_M 全链路先通（白名单内 + dense loop，零自研）→ 再调 IQ2/Q2；热集 pin ~34% 模拟 35B 失真要求不变；llama.cpp 对 tiny 架构（bailing hybrid + KDA）的 GGUF 支持待 P1.0 核对
P2
专家分层 + 调度四件套落地
判定物：冷专家 miss 不 stall 的流水线实测
P3
自研内核：Q2_K → IQ2_XS + dense loop MoE
判定物：数值门 + 带宽效率 vs iq4_nl 同级
P4
35B-A3B 真身上机
判定物：17–20 或 6–9，定案
2

A / B 双内核线分开管理

A 线 · 通用 GEMV（OpenCL / GPU）

Q4_K_M 先通 → Q2_K → IQ2_XS。服务 dense 部分 + Ling 代理全链路 + 未来备选专家格式。
工期：Q2_K 2–3 天（复用 q4_K 超块骨架 + 2bit 解包，零 codebook）；IQ2_XS 3–5 天（复用 iq4_nl 的 16 条目 codebook + 新增 2bit/scale 解包）。
验收：每层 9 次调用 × ~32 层 ⇒ gate+up 融合砍 launch 数。

B 线 · T42 专家（CPU）

GSQ T42 2.25bpw 是 35B 专属格式，A 线只复用方法论不复用代码；P3 落地。若 T42 内核失败 ⇒ fallback = 专家转 IQ2_XS（A 线成果在此接上）。
