总纲1/9

三步走全景：每一步都留下「可复用的判据」

三步的价值不在「哪个更快」，而在把每条机制的适用边界钉死——第三步正落在前两步的夹缝里。

① 同构 · 5060 Ti 16G

做什么：在 llama.cpp fork 上复刻 Strata 机制。

量出什么：prefill 成本 ∝ 窗口内专家重拷贝次数（ub 512→2048：pp 32–72 → 260–372，零代码）。

证伪什么：GPU 专家热缓存（3G vs 40.9G 专家，命中≈0，tg 34.7→15.9）。

② 异构 · DGX GB10

做什么：把同一套机制移植到 ARM64（Grace + Blackwell + 273 GB/s 单池）。

难点在哪：全在 CPU 侧（arm_compat.h + 43 个 ISA 桩）；CUDA 内核零改动。

证伪什么：统一内存下分层 / 预取 / pinned 池 / KV 搬运失去作用对象。

③ 端侧 · 手机 16G

做什么：让 35B-A3B 在骁龙 8 Elite Gen 5 上能跑、能吐字。

为什么有戏：内存比 5060 Ti 还紧 ⇒ 步骤二证伪的那批机制集体复活。

门控在哪：不在算力、不在带宽，在「冷专家命中时不能 stall」。

第一步2/9

同构：在 5060 Ti 上把 Strata 的机制复刻成可测的 fork

目的不是「超过 Strata」，而是把流式专家推理的成本结构量清楚：哪一项是算力、哪一项是拷贝、哪一项是调度。

① prefill 的瓶颈是「重拷贝次数」

512-token 窗口内 unique 专家 ≈ 511/512 ⇒ ub=512 时每个窗口要重流约 40 GB 专家。

ub 提到 2048：pp 32–72 → 260–372，零代码改动。

⇒ 成本 ∝ 窗口内专家重拷贝次数，不是算力。

② 深草稿 MTP 是白送的

默认 n_max=4 时 mean len 被截在 3.97；放到 8 后逐位接受率几乎不掉（0.93×5 + 0.87×3）。

mean len 3.97 → 8.27，tg 33–38 → 40.83。

⇒ 收益 ∝ 一次权重读取服务的 token 数。

③ 跨档位不可迁移的机制

GPU 专家热缓存 --moe-cache-mib 3072 只覆盖 40.9 G 专家的 7.5%，命中 ≈ 0，tg 34.7 → 15.9（倒贴）。

⇒ 论文的 0.72 命中率属 24G 卡档位。

「硬件墙」假说破产：同一台机器上 Strata 做到 pp 1310 / tg 61–68（且跑得更狠，avail RAM 只剩 0.4 G）， fork 只有 ~250 / ~38。差距 = fork 完成度，不是显存档位。根因四件套全缺： expert-profile 预填热缓存（头部 18% 专家覆盖 80% 访问）、resident arena、 prefill 传输/计算流水、命中分组 GPU kernel。
遥测对照：Strata 预填 GPU 热缓存 4502 槽 / 7.5 G，RAM arena 32 G，hit_rate 0.78–0.85， 解码期 PCIe 流量 ≈ 0；草稿接受率仅 0.81 / mean 1.7 仍跑出 tg 61–68。 ⇒ 分层调度的收益来自「命中率 × 命中路径不落盘」，与草稿质量无关。
第二步3/9

异构：同一套机制搬到 ARM 统一内存，一半失效

DGX GB10 = Grace（ARM64）+ Blackwell + 273 GB/s 单池 LPDDR5X。移植难点全在 CPU 侧，CUDA 内核零改动。

三个边界判决

判决 ① 机制失去作用对象

统一内存下 专家分层 / 预取流水 / pinned 池 / KV 搬运整类机制没有可作用的对象——24,576 个专家全部常驻，没有「拷贝」要避免。

⇒ 5060 Ti 的 PCIe 类优化搬到 UMA 上整体失效。

判决 ② 带宽真相被校准

GB10 = 16 通道 × 16-bit = 273 GB/s 单池，不是「4 通道」。

零拷贝读实测 ≈225 GB/s——旧报告「host 注册内存只有 87–127 GB/s」是测量假象（尺寸不匹配 + block 数踩劣化区 + 机器不空闲）。

真正慢的是拷贝引擎：H2D 50、D2H 30 GB/s。

判决 ③ 瓶颈是 kernel 粒度

decode 每步必读 ≈1.6 GiB，实测 52.9 ms/步 ⇒ 有效带宽 ≈30 GB/s = 峰值 12%；算力占用 <1%。

根因：每步 约 500 个小粒度 kernel 串行（MMVQ 单 block 访存 ~3 KB；SSM scan grid=24 只占 48 SM 的一半）。

⇒ 不是带宽墙、不是算力墙，是 kernel 粒度墙。

结论反转：UMA 上唯一杠杆是「每 token 少读字节」+ occupancy / 并行度； 「先搬进设备内存再算」反而是窄口（设备-local 仍快 ~10%）。另：投机在 DGX 上是实打实的 1.6–2.2×——这条到手机端会反向。
终局 A/B（同场景 serve · 256 tok 输出）：SHORT 创作 34.2 vs 36.8／REPEAT-t0 冗余 42.4 vs 59.2 ⇒ GB10 上 llama.cpp 全面快于 Strata 引擎。⇒ 引擎整体弃用，只留 MoE CUDA 内核 + 投机。
第三步4/9

CUDA 上「改代码就生效」的假设，在手机上不成立

同一个 llama.cpp，在四种后端上的可用内核集合、正确性、可预测性是不同的世界。方案必须从这个约束出发，而不是从模型出发。

CUDA · 5060Ti / DGX 低风险

量化类型全（含 IQ2_S / IQ3_S / IQ4_XS），MoE MUL_MAT_ID 全类型，编译器成熟稳定。

真机结论：改代码即生效。

OpenCL · Adreno 中风险

量化白名单约 11 种：q1_0 q4_0 q4_1 q4_K q5_0 q5_1 q5_K q6_K q8_0 iq4_nl mxfp4，整个 IQ 家族缺席。

MoE 通用仅 Q4_0 / Q8_0 / MXFP4。编译器有坑：__constant 数组变址被错编（已用三元表达式绕过）。

真机结论：可用——自研 PTQ1_0 内核 test-backend-ops 174/174。

Vulkan 原厂 不可行

三类 bug 并存：错编数值 / 拒建 compute pipeline / 静默挂死。

真机结论：从未跑通——6 次端到端 CLI 全部乱码或崩溃，0 次正确。

Vulkan Turnip（Mesa） 高风险

需三药：subgroup 算术错编 + GDN S_V=128 shmem 布局错编 ⇒ NO_SUBGROUP + lanes 钳位 64。

真机结论：能跑但慢——三药后 e2e 连贯，仅 5–11 t/s。

第一性约束：量化格式不能「先选格式、再找内核」，必须从后端内核白名单反推。 上一版建议的「T42 → 重打包成 IQ2_S」在 OpenCL 上是死路——IQ2_S 连一般的 MUL_MAT 都没有内核。
① 后端选择是一次性决策

手机上可用的 GPU 路径实际只有 OpenCL；Vulkan 两条路从主线排除，只留作日后驱动更新的复测项。

② 格式被白名单锁死

只要专家上 GPU，最小只能到 MXFP4（4.25 bpw）。T42 的 2.25 bpw 在 GPU 上无内核。

③ CPU 是唯一「格式自由」后端

ggml-cpu 支持全部 GGML 类型。专家留给 CPU，是唯一既不损失体积、又不碰自研 GPU 内核的路。

第三步5/9

35B-A3B 不是「小一号的 Flash」，它换了三个决定成败的结构

前两步围绕 Qwen3.8-Flash-Next（qwen4exp）。目标 Qwen3.6-35B-A3B（qwen35moe）在专家表规模、存储依赖、优化比重上截然不同——恰好决定手机端该怎么做。

为什么「专家表小」是决定性的：热集覆盖率算一遍

Flash · 假设 3 GiB 热集预算
3 GiB ÷ 2.31 MiB = 1,330 个专家可常驻
摊到 48 层 = 27.7 个/层；每层 512 个 ⇒ 覆盖率 5.4%

这正是 DGX 上「专家热缓存没有作用对象」的同一条算术。

35B · 同样 3 GiB 热集预算
3 GiB ÷ 0.844 MiB = 3,640 个专家可常驻
摊到 40 层 = 91 个/层；每层 256 个 ⇒ 覆盖率 35.5%

覆盖率高出 6.6×。只要热度不是均匀分布，top-35% 完全可能覆盖 70%+ 的选择。

这就是「分层机制在手机端复活」的数学原因：不是内存更小就自动该分层，而是35B 的「256 专家/层」让每层热集第一次能达到 30%+ 覆盖率。
待实测（不要当结论用）：35.5% 是「容量覆盖率」，实际收益取决于路由热度的集中度。必须用真实对话样本统计热度表来验证。
一句话：Flash 的瓶颈在专家与 KV；35B 的瓶颈在 dense 权重与输出头。手机上第一优先是词表子集手术。

第三步7/9

手机版 Strata 三层：把 UFS 当作虚拟内存用

手机没有可用的 swap——ZRAM 是「压缩 RAM」，对已量化的权重压缩比接近 1；写回式 swap 还会成倍消耗 NAND 寿命。真正可用的只有一条：UFS 上的 file-backed mmap，靠内核「干净页可直接丢弃、不需要写回」的语义。

三层存储（对照 Strata 的 GPU / CPU / SSD）

L0 · Adreno 侧匿名内存 · 热集  1.5–2.5 GiB
放什么：per-layer pin 的热专家 + KV cache（q8_0）
带宽：~85 GB/s 峰值（与 CPU 共享同一 LPDDR5X 单池）· 延迟内存级
回收语义：匿名页不可丢弃 ⇒ 这里必须放最热的东西
对应 Strata：expert-cache + --expert-cache-per-layer（DGX 实测该一条把 per-layer 命中率从 54% 拉到 99%）
L1 · CPU Oryon 常驻匿名内存  3–5 GiB
放什么：dense 骨干 + 中热专家 + 正在计算的冷专家
算力：2×Oryon Prime @4.6GHz + 6×Performance @3.62GHz，无小核，24MB 缓存
带宽：与 GPU 共享同一 LPDDR5X 池——双路并行会互相争抢，必须实测
格式自由：ggml-cpu 支持全部类型，包括自研 T42
L2 · UFS 4.1 file-backed mmap · 冷专家  5.06 GiB
放什么：未被 pin 的冷专家，以只读文件页形式 mmap
吞吐：顺序读 4.3 GB/s；4K 随机读 590K IOPS · QD1 随机读延迟 ≈100 µs
回收语义：干净页可被内核直接丢弃，不需 swap、不写回——这是它比 ZRAM 更适合权重的原因
核心风险：单个专家 0.844 MiB = 216 个 4K 页，216 × 100 µs = 21.6 ms——如果按「页故障」触发， 只要一层命中一个冷专家就吃掉一整步的时间。L2 的正确用法不是「按需缺页」，而是「按预测提前异步读进 L1/L0」。

调度四件套（逐条对应 Strata 的机制）

① 热度表 · 离线统计

跑一批真实对话样本，统计「每层 × 每专家」被 router 选中的频率，产出 pin 优先级表。对应 Strata 的 expert-profile，是后面三件事的输入。

② per-layer 填充

热集预算 ÷ 40 层 = 每层常驻配额。3 GiB ⇒ 91 个/层 = 35.5% 覆盖。必须按层分配，不能全局共用——Strata 实测最有效的一条。

③ 超集异步预读（最关键）

绝不能靠 4KB 页故障。要做的是批量 pread / MADV_WILLNEED 异步发起，并按超集预取——读 top-32、只用 top-8。多读的字节远便宜于一次 stall。

④ 预算切分（KV ↔ 专家热集）

两者争同一块匿名内存。35B 的 KV 只有 10.9 KB/token，64K 也才 0.65 GiB ⇒ 大部分预算可以给专家热集。

第三步8/9

要压的不是专家，是 dense 的 Q8_0

直觉上「更低量化」＝把专家的 2.25 bpw 再往下压。但把每 token 字节账摆开就会发现这条路是死的：专家只占 12%，而占 85% 的 dense 用的却是 8.5 bpw 的 Q8_0。唯一有 40% 以上下降空间的地方在那里——而且全部落在 OpenCL 内核白名单内。

结论9/9

评级下调为「中等」：风险从硬件搬到了软件机制

上一版给的是「中等偏高」，隐含假设是「手机 GPU 后端像 CUDA 一样听话」。核实后端能力与架构差异后，这个假设不成立。但要注意：下调的不是「能不能跑」，而是「跑多快、要多少工程量」。

落地顺序（每步都有证伪判据）

P0 · 能力探测

目标机跑 test-backend-ops，产出 OpenCL / Vulkan 的「类型 × 算子」白名单 + 实测有效带宽。

这是所有决策的输入，先做。

P1 · 双路骨架（被低估的一步）

选一个 Q4_0/Q8_0 的小 MoE 模型——catalog 里已有 lfm2.5-8b-a1b-ud-iq3_xxs（3.05 GB，MoE A1B），是 A3B 的天然缩比代理——验「GPU dense + CPU MoE」的 split graph 行为，测两路耗时占比与带宽争抢。

判据：CPU 侧耗时占比 < 55%。

P2 · 专家分层

热度表 + per-layer pin + 超集异步预读。工程量最大的一步。

判据：冷专家命中不产生可见 stall。

P3 · T42 CPU 内核

dequant + vec_dot（NEON / i8mm）。可直接复用 PTQ1_0 OpenCL 内核踩过的坑与验证方法。

P4 · 上 35B

扫热集预算（3.0 / 3.5 / 4.0 GiB）× 预读深度 × 线程数，找稳态最优。

最终评级：中等。门控不在算力、不在带宽，而在「冷专家不 stall」。 乐观稳态 17–20 t/s（热集覆盖 >35%，且 UFS 预读与 dense 计算完全重叠）； 悲观 6–9 t/s（UFS 随机读藏不住，每次冷专家命中 stall 一整步）。 两者之间没有中间态好猜——这正是 P0/P1 要用很低成本先量出来的东西。
