三个边界判决

判决 ① 机制失去作用对象

统一内存下 专家分层 / 预取流水 / pinned 池 / KV 搬运整类机制没有可作用的对象——24,576 个专家全部常驻，没有「拷贝」要避免。

⇒ 5060 Ti 的 PCIe 类优化（专家热缓存 / pinned arena / DMA 流水 / ring 槽位）搬到 UMA 上整体失效。

判决 ② 带宽真相被校准

GB10 = 16 通道 × 16-bit = 273 GB/s 单池，不是「4 通道」。

零拷贝读实测 ≈225 GB/s（≈ 设备读 250 的 90%）——旧报告「host 注册内存只有 87–127 GB/s」是测量假象（尺寸不匹配 + block 数踩劣化区 + 机器不空闲）。

真正慢的是拷贝引擎：H2D 50、D2H 30 GB/s。

判决 ③ 瓶颈是 kernel 粒度

decode 每步必读 ≈1.6 GiB，实测 52.9 ms/步 ⇒ 有效带宽 ≈30 GB/s = 峰值 12%；算力占用 <1%。

根因：每步 约 500 个小粒度 kernel 串行（MMVQ 单 block 访存 ~3 KB；SSM scan grid=24 只占 48 SM 的一半）。

⇒ 不是带宽墙、不是算力墙，是 kernel 粒度墙。

结论反转：UMA 上唯一杠杆是 「每 token 少读字节」+ occupancy / 并行度； 「先搬进设备内存再算」反而是窄口（虽然设备-local 仍快 ~10%）。 另：投机在 DGX 上是实打实的 1.6–2.2×（无投机 18.9 t/s vs 有投机 30.5 t/s）——因为草稿权重几乎免费。这条到手机端会反向。
终局 A/B（同场景 serve 模式 · 256 tok 输出）：SHORT 创作 34.2 vs 36.8／REPEAT-t0 冗余 42.4 vs 59.2 ⇒ GB10 上 llama.cpp 全面快于 Strata 引擎。⇒ 引擎整体弃用，只留 MoE CUDA 内核 + 投机；资产（pack / rt 转换链 / 配置）保留可一键拉起。
