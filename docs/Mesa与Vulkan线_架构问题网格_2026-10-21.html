Mesa(OpenCL) 线 与 Vulkan 线 · 架构层问题网格

日期：2026-10-21 00:0x　范围：自研 Mesa 栈（rusticl + freedreno/ir3 + 我们的 kgsl winsys）与 Vulkan 线（内置 turnip） 性质：方法论 + 可执行网格。本文件是"问题"的唯一登记处；其它文档只许引用格号，不许新增问题条目。 上游文档：Mesa线接管复评与重规划、 L3 裁决、 Mesa 自研路线总档（上位）、 主线遗留备忘清单、 Vulkan 数值修复专项、 Vulkan 线立项与隔离约定、 端侧推理自研架构方向评估

0. 先说清楚"顾头不顾腚"是什么病，不是"太复杂"

复杂度不是病根（Vulkan 线今天一天拿下 subgroup 族，栈一样深）。病根是问题的表示法是一维的： P0…P8 + §8…§19 是按发生时间排的一维清单，没有"位置"这一维。四个必然后果，全部已在今天的档案里发生：

病 形态 档案实据 后果
B1 假设跨层漂移 一个条目不带"它在哪一层"的强制字段，于是假设可以搬家而无人重算 P2 病灶六次搬家：rusticl 队列 → kgsl winsys → libdrm 2013 ringbuffer → 17:35 勘误收回 → sp/ringpool → 我们自己的融合内核 → BO/ring 复用 每次搬家都重付一遍学费；"已排除"其实是"排除了当时那一格"
B2 无作用域的清白 仪器没接通时的"无差别"被记成"已排除" FD_MESA_DEBUG=inorder/nogrow 观测量逐位相同（串在≠通路在）；FD_RD_DUMP* 目录恒空；ALLOW_NO_SUBGROUP=0 整条退 CPU 后"token 全等"（同义反复的 PASS） 假清白堆积 → 后期只能反复重测，感觉永远在原地
B3 证据无主键 数字不带"哪颗 lib / 哪套 env / 哪台机 + 是否安静" 8.07 t/s 反复复活；"上午 3.7 tok/s 是 07:48 那版 APK，与设备上 13:54 版不是同一二进制"；CPU 腿同批漂 1.5–2.2× 污染数被反复引用 → 裁决作废 → 重做（今天已因此作废一整版结论）
B4 单实验多变量 一次实验同时动两层的变量，却给单格判清白 K40 不复现同时改变了世代(gen6/gen7) 与模型量化(mix_q3gud_im vs 830 那颗) ⇒ "gen6 不复现"不能给 gen7 提交层清白 排除法失效，六条"已排除"里有几条其实没排除

一句话：问题清单 缺"位置"维，所以谁都得用人脑记住"哪些格子已经排除了"。人脑一溢出，就是顾头不顾腚。 对策不是"更努力排查"，是把问题变成二维（栈位置 × 失效模式）+ 一列可改性，并且把排除的权限交给机器。

读这张图得到三条架构级结论，比任何单个 bug 都重要：

  1. L1 是同一个洞，L2 是两份代码、两套判具、两套结论。 这就是"太复杂"的真正来源：底层同一个物理问题 （提交是否完整、IB/BO 生命周期、fence 语义、EAGAIN 处置），上面互不相通。 OpenCL 线在 L2/L1 学到的每一件事，对 Vulkan 线的 L2 零传递。 ⇒ 先做的不是选边，是建一份《KGSL 提交层契约表》+ 一套两线共用压测断言（见 §6-A）。
  2. L2 是我们唯一"自研但源码不在手"的层。 P0-1 卡住的从来不是"整个 Mesa 树"，恰恰就是 L2 （kgsl/*.{c,h} + fd_batch/fd_submit 的 FD_ 改动 + fix_fd_device.py 打的洞）。 而 P2 今天唯一剩下的候选（BO/ring 复用）也落在 L2。 ⇒ 整条线有一个单点故障，形状是"资产失控"，不是"技术难题"。* 网格化的第一个产出的就是把这件事从待办清单里拎出来。
  3. L3 已经给出过一次"架构做法赢"的样板。 Vulkan 线用 driver×device_class 数据表 + vk_gate.sh + 反向对照（FORCE_SUBGROUP_ARITH=1 能把 FAIL 打回来 ⇒ 证明门禁有牙），一天拿下三个坏 op； 同一类"能力宣称"问题在 OpenCL 侧（藏 cl_khr_subgroups、缺可写 3D 图像）今天还散在 env 与注释里。 ⇒ 把这三件套上升为两线共同的架构约束，而不是 Vulkan 线的独占成果。

3. 第三步：定可改性轴（决定这格"可打 / 只能绕 / 只能认"）

标记 含义 网格规则
OWN 我们自己的代码（L6/L7/L8 + 我们的 kgsl winsys） 可打。默认优先级最高
OWN-BLOCKED 我们的代码但资产不在手 算阻塞，不算待办；阻塞解除前该格不许占用排查预算
UP 上游 Mesa/ggml 语义 只能读 + 打 patch；任何修复必须是"可重放补丁 + 上游可提"
BLACKBOX 闭源 KGSL 驱动/固件、厂商 CL 编译器 必须自带"不依赖修改的观测判据"，否则不是待办，是死账 → 标 UNREACHABLE，转"跟踪上游/上报"
HW 硬件/世代能力缺失 分两种：能力缺失→绕；性能上限→认（写进预算表，不再投人）
