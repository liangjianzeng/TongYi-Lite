# 全 GPU 路线 · 差距总账与作战计划（2026-10-20）

> 回答一个问题：**距离终局还差多少工作、每一步的验收判据是什么、还要多久。**
> 本文档取代《三线合一总档》§12 作为当前唯一生效的路线图；此后每周收账一次，只改本文档。

## 一、终局目标（Definition of Done）

**目标设备矩阵（2026-10-20 用户定档）：主目标 830 / 825 / 840，底线 740。K40（Adreno 650）只是调试机，不进目标矩阵。**

**终局验收（以 830 为基准主战场）**：生产模型 MiniCPM-V4.7-les（35B-A3B，15GB 拆分包），rusticl+kgsl 栈全 GPU 推理（全图单后端、零 CPU 专家岛、零跨后端拷贝），无需 OPFLUSH 等 workaround 数值健康（强制 token 与 CPU 对齐），decode t/s 反超该机 CPU bank 生产基线 8.07，目标 8-10 t/s。**收口扩展**：同一套栈在 840 / 825 跑通生产配置，740 验证可用（底线：不要求达标，只要求数值健康 + 不输该机 CPU）。

### 设备角色矩阵

| 设备 | 角色 | 栈现状 | 在本计划中的用途 |
|---|---|---|---|
| **830**（warsaw/SM8750） | **主战场 + 基准机** | rusticl+kgsl 全链路跑通；race 未根治（OPFLUSH=1 标配） | W1-W6 全部战役的验收机；终局 t/s 判定在此 |
| **840** | 主目标 | **未侦察**（栈可行性、SELinux、kgsl 路径全未知） | W2 门禁扩容时加跑 tbo；W6 前完成 M0' 级探针（1-2 天） |

## 三、计划必须吸收的两个新事实（10-19/10-20 实测）

1. **race 未根治，但从未挡住 K40**。830 上 OPFLUSH=1 仍是标配（晚提交 race：gallium batch 多 launch ≤9 健康/32-48 碎片化，靶子已收窄到 freedreno batch state emit + kgsl flush_submit_list）；K40 同栈无需 OPFLUSH（q8_0 修复后三翻案：融合健康、OPFLUSH=0 健康、"GEMM 部分坏"是 dump 伪影）。⇒ race 是 830 特有的 Mesa 缺陷，可修、靶子明确。
2. **per-op 开销是 3 个数量级的墙，提交税不是主项**（⚠️ K40 调试机口径，方向性参考而非定量）。K40 可比基准（同机同模型同二进制，无全部混杂因子）：GPU tg128 = 2.28-2.53 vs CPU 18.4-18.8 t/s（7-9 倍差），0.5B decode ≈200-400 op/token ⇒ **每 op ~1-2ms，而 M0 判据目标是录制 <3µs/op**；且 OPFLUSH=0 反而更慢 ⇒ clFlush 零成本，开销在别处（执行/同步/等待，未拆账）。⇒ 《总档》§8「M2 砍掉 36ms 提交税 → 5.9 t/s」的推算基础不完整，M2 前必须先解剖 per-op；**W3 的定量结论必须在 830 上复核**（a650 无 subgroup、代际差两代，绝对值不可外推，结构占比预期可迁移）。

## 四、剩余战役分解（W1-W6，关键路径）

### W1 · Mesa race 根治（830）｜估 1-2 周｜不确定度最高
- **内容**：freedreno 同 batch 多 launch 的 state emit（cb0/SSBO dirty tracking）→ 修 mesa 本体或每 launch flush（FD_MESA_DEBUG=flush 已证有效，转正为默认）。
- **验收**：830 上 OPFLUSH=0（含 DISABLE_FUSION=0）自由生成文本与 CPU 参照 48 token 无碎片化；三机回归全绿。
- **失败兜底**：FD_MESA_DEBUG=flush 路径转正（纯 mesa 侧、每 launch 一次 flush，性能实测待做）。
- **★ 10-20 新证据（K40）：MUL_MAT_ID 套件 22 FAIL + GPU hang（KGSLSUBMIT ret=0 → KGSLWAIT EDEADLK → fence 永不 signal）= race 第三形态**。已排除：base GEMV kernel（MUL_MAT twins 全绿）、image-from-subbuffer 偏移（clprobe26 三测全绿）；batched/dense-loop 双管线同坏、OPFLUSH=1 不防。**race 触发面从 e2e 文本扩到 tbo 提交模式，K40 成为 race 最快复现载体（USB + 数分钟）**。W1 完成后 MUL_MAT_ID 22 FAIL 一并回归。
- **★ 10-20 夜 W1 预研（K40 A/B 矩阵）：race = 两个独立窗口**。①数值窗口（§34 形态）：FD_MESA_DEBUG=flush 与 RUSTICL_DEBUG=sync 均把 22 FAIL→0；②**hang 窗口（新形态）：flush 不修**——载体精确定位 = set_tensor q4_K convert kernel 的 304B 单 launch 提交（ret=0 → GPU 未执行 → fence 永不 signal → EDEADLK），HANGDUMP 实测 hang 时 `gpubusy≈0.015%`（GPU 全闲）= **cmd 丢失/未入队执行坐实**，概率 ~1e-4/提交，convert 提交密度高的 workload 必中。W1 验收必须含 hang 窗口（tbo MUL_MAT_ID 双回归 + 830 e2e 长跑）；FD_MESA_DEBUG=flush 转正只覆盖数值窗口。

### W2 · M1 收尾：内核门禁普适化｜估 1 周｜确定性高 → **K40 闭环 ✅；830 MUL_MAT 全绿 ✅；MUL_MAT_ID 双机双形态已定性（10-20 晨）**
- **已完成（K40）**：① GEMV 全族 11 量化类型 × m=64..512 sgs 脆弱性扫参，病毒载体 q4_0/q1_0，已按 per-lane 全 K 范式修复（GGML_OPENCL_RUSTICL 门控），全量 MUL_MAT 1863/1863 + e2e 双 golden 逐位一致；② 830 全量 MUL_MAT 门禁 2/2 backends 同步通过；③ mc3（spec verify 多列 GEMV）五家族探针：**rusticl 上数值损坏实锤（8 用例）但全部 opt-in 默认关，生产零影响，记录不修**（若将来 rusticl 栈启用 spec/MTP 再 per-lane 化）；④ MUL_MAT_ID 22 FAIL 定性为 race 第三形态（转 W1，见上）。
- **830 补测定案（10-20 晨，tbo md5=4167cafb）**：⑤ MUL_MAT 复跑 2/2 全绿（首轮 3 FAIL 为 race 数值窗口偶发泄漏——OPFLUSH=1 下 tbo 高密度提交仍有残余，W1 验收回归须多轮）；⑥ mc3 开启对照 q4_K n=3 NaN 与 K40 同型 → mc3 损坏双机确认；⑦ **MUL_MAT_ID 双机双形态定性**：830 batched 路径 = q_img clCreateImage **-40**（host 可见确定性，ggml-opencl.cpp:25156；K40 同代码不触发）+ dense-loop = **74 FAIL 全 q4_K m=512 确定性数值坏**（同形状 MUL_MAT twins 全绿 → 管线特有，SoA/seff prep 嫌疑；K40 则 q4_0+q4_K 双坏）——**两机坏法不同，race 不能解释全部，W2 遗留真 bug 待修**。
- **W2 收口判定**：MUL_MAT 双机全绿；MUL_MAT_ID 修复为独立工作项（先修 830 batched -40 → dense-loop q4_K，再以 K40 22 FAIL 回归收口），不阻塞 W3 定量（W3 用 MUL_MAT 路径 + probe9）。
- **probe9 定量（W3 判据）**：moe_probe9 在 830 缺 NDK STL 符号（__ndk1）→ 需 DGX c++_static 重编后重推。
- **待 830**：q4_K batched NMSE 对 vendor 同级验证；q3_K batched 全形状门禁（moe_probe 工作流）；830 e2e 双 golden。
- **840**：到位即跑 M0' 级探针（clinfo + q4_K GEMV 标尺 + 录制税斜率，1-2 天，不占关键路径）。

### W3 · per-op 开销解剖探针｜估 3-5 天｜**新插入的关键节点**
- **内容**：把 ~1-2ms/op 拆成内核执行 / 提交（ioctl）/ fence 等待 / host 录制四项。工具：CL_QUEUE_PROFILING 被拒（-35）用 wall 口径 + KPERF 式批量斜率；kgsl ioctl 计数（mesa 插桩库现成）。
- **验收（判据即分叉）**：若大头=内核执行慢 ⇒ M2 收益有限，M3（融合减 op 数）提前为第一优先；若大头=提交/等待 ⇒ 原版 M2（批量 flush/重放）打法成立；若大头=host 录制 ⇒ 走手写 runner 分支（+2 周）。**定量复核在 830 上做**（K40 只出结构占比假设）。
- **为什么必须先做**：M2 的 1-2 周投入方向完全由这一步决定，不做就是赌。

### W4 · M2 整图单提交 + UMA 直写｜估 1-2 周（W3 判据后）
- **内容**：decode 图录制一次多 token 重放（或每 token 单次 batch flush）；freedreno 天然 UMA，FGSVM→gpuobj mmap 直写（同治 pread 反噬）。
- **验收**：830 x7 真实全 GPU t/s（估 ≥5.9）；MiniCPM-les 830 全 GPU 腿出数。
- **风险**：重放需要图拓扑不变（decode 图满足）；race 修复是硬前置（单 batch 更大更脆）。

### W5 · M3 小算子融合｜估 2-4 周｜质变点，赢 CPU 全押此
- **内容**：norm+rope+GEMV 链、SSM_CONV+SCAN、逐层 megakernel 化；3941 ops→几百个。ir3 可读可改是核心优势（编坏修编译器本体，对比 E031 只能 dodge）。每 kernel 过 NMSE 门禁。
- **验收**：830 MiniCPM decode ≥8.07（反超 CPU 基线）＝**终局判据达成**。

### W6 · M4 集成｜估 2-3 天
- **内容**：moe_probe/minicpm_e2e → 生产链路；**830 生产配置切换 → 840 / 825 收口验证 → 740 底线验证**；K40 只留作调试机不进交付矩阵。
- **验收**：830 达终局判据（≥8.07）；840/825 跑通生产配置（数值健康 + t/s 实测入账）；740 数值健康且不输该机 CPU（2.5 t/s）；App 级装载（TongYi-Lite 0.3.x split-MoE 链路接 rusticl 栈）在 830 跑通生产 prompt。
- **825 特别兜底**：若 Mesa 栈在 825 上不可行（驱动代际/SELinux 墙），App 现行 vendor OpenCL 白名单路径继续供货，Mesa 线只覆盖 830/840/740——不影响 App 发布。

### 叠加线（非关键路径，W4 后并行）
- **dspark G3-G5**：dflash/GDN 内核 rusticl 编译 + 数值门（G4）+ 窗口冷热表/Hook-3/accept≥2.0（G5）。draft 上 GPU 前提已被旧栈实测锁定（accept 1.88 < 打平线 3-4.3）。
- **天玑线**：M2/M3 定型后启动；M0' 探针（/dev/mali0 SELinux + vendor blob 存在性）可在设备到位后 1-2 天先行。

## 五、工期总账与不确定性

| 情形 | 关键路径 | 说明 |
|---|---|---|
| 顺利 | **~5 周** | race 一击即中（FD_MESA_DEBUG=flush 转正）、W3 判据支持原版 M2、融合只做 norm+GEMV 链 |
| 基准 | **6-9 周** | 与《总档》"工程量月级"估计一致 |
| 逆境 | 10-12 周 | race 是驱动级难啃 + W3 判据指向手写 runner（+2 周）+ M3 融合波次增多 |

- 已沉没/已兑付的部分：M0 + 正确性战役 ≈ 总工程量的前 1/3，且是风险最高的 1/3（两个"整线死刑"判据都已过）。
- 保底始终存在：CPU bank 生产配置（830 8.07 t/s）不受本线任何失败影响；本线失败=收益归零，不是功能归零。

## 六、验收纪律（沿用测量铁律）

所有 perf 结论走：同轮同组交错 + 冷却 ≥150s + 中位+全样本（K40/740 连跑热降频均已实测）；数值结论走：强制 token 对齐 CPU + tbo 门禁 + NMSE；同名节点 dump 前必须用 `[nd] op=` 字段确认身份（Vcur-0 伪影教训）。**设备口径纪律：K40 数字只用于调试决策，不进入目标机评估；目标机结论一律出自 830/840/825 实测，缺数据就标 TBD，不用 K40 代答。**
