## 一、任务目标

**战略铁律（多轮继承）**：MiniCPM-les MoE 推理全部跑在自研 Mesa rusticl + freedreno(ir3) + kgsl 栈上，修通无投机全 GPU 推理并出真实 t/s（M2 里程碑）。

**本会话具体目标**：攻克「GPU 批量模式下 conv 状态 gather（GET_ROWS）读零 → logits 全零/垃圾」这最后一个正确性拦路虎。它表现为三层症状：

1. 纯批量生产模式 logits 全零流；
2. 逐节点审计（CBD armed）模式健康、一关就坏；
3. GPU leg 的 logits 恒在 9–11 区间，而 CPU 健康值在 32 上下。

**目标定位澄清（通用性）**：全 GPU 卸载面向**所有 MoE 模型**，非单模型优化。MiniCPM-V 4.7 只是攻坚载体——它既是目标模型 Qwen3.6-35B-A3B 的同构代理（qwen3_5_moe 族），也是最严苛压力测试（最大端侧 MoE + 线性注意力混合 + 最长 conv 状态链）。本会话全部修复资产的受益面：

| 资产 | 层级 | 受益模型面 |
|---|---|---|
| sched per-split 注册修复 | 框架层 | 全部模型（任何跨后端 gather 图） |
| Mesa rusticl/freedreno+kgsl 栈 | OpenCL 层 | 完全模型无关，dense 模型也受益 |
| batched MUL_MAT_ID 三档 | 内核层 | 所有 MoE 已验证量化档 |
| 常量 idx | RS cache 层 | 含 Mamba/线性注意力的混合 MoE；纯 GQA 模型无此路径也无此 bug |
| logits 读回修复（进行中） | 框架/驱动层 | 全部模型 |

路线图：MiniCPM 载体验证（现在）→ Qwen3.6-35B-A3B 原样上机 → 通用 MoE 全家族（LFM2.5-24B-A2B、Ling 系）→ dense 模型白拿 Mesa 栈收益。

## 二、本会话做了哪些工作（逐条）

1. **延续上轮根因追踪**：从「批量模式 GET_ROWS 读零」的 sched 分配映射（GGML_SCHED_DEBUG=2）与 83-split 结构出发，逐 split 审计 cross-backend 输入注册行为。
2. **根因全案告破（sched 单次注册 + ggml-alloc 区域回收）**：改 `ggml-backend.cpp` pass-5，把 `split->inputs[n_inputs] = src` 移出 `if (tensor_id_copy(...) == NULL)`——上游同构 bug，非移植错误。
3. **修复效果实证**：idxval 376/400 归零；logits 从全零 → 9.9–11.4；margin 0.19→1.34（e2e_accept1）。
4. **残留 L2 垃圾排查**：同 queue、同 cl_mem、同 offset，写后立读=0、gather 读=垃圾——形式因果违反。排除双队列/队列乱序/SVM 路径/写丢失，常规手段打尽后判定收益递减。
5. **常量 idx 方案设计与实施（8 处改点）**：
   - `llama-memory-recurrent.{h,cpp}`：`s_copy_c` I32[n_rs] 常量张量（RS cache buffer 内，清零即 [0]）+ accessor `get_s_copy_c()` / `s_copy_is_const_zero()`；
   - `llama-graph.cpp` `build_rs_inp_impl`：`LLAMA_RS_CONST_IDX=1` 门控切换，跳过 input 创建与 host 写；
   - 4 处 `set_input` 加 `!const_idx` 守卫；4 处 `can_reuse` 加模式翻转拒绝；
   - 编译期修了 helper 定义位置（移文件头）与重复定义。
6. **常量 idx 上线验证（rscidx1）**：logits 全序列改变 = 路径生效；n_rs>1 自动回退正常路径，无回归风险。
7. **判别实验 BATCHED_MOE=0**：GPU dense（MoE 与 CPU 同路径）step1 max 依然 9.35 ⇒ 问题不在 batched MoE，分头排查 GPU dense/conv 链。
8. **CBD 逐节点审计战役（本会话核心成果）**：
   - CPU leg 77655 节点 vs GPU leg 78656 节点全量 dump；
   - 语义节点名配对（剔除匿名 node_N 编号错配）；
   - 逐层误差热图 + decode step-1 逐节点误差表 + 输出链 max 演化；
   - 结论：31 个 result_output occ（prefill 22 ubatch + decode 9）CPU/GPU 全对齐（<3%）。
9. **同步机制全谱证伪**：`llama_synchronize`（E2E_LGD_SYNC）、每 split `clFinish`（新 knob `GGML_SCHED_FORCE_SPLIT_SYNC`）、稀疏节点同步（`E2E_CBD_ONLY=result_norm/result_output/norm/node_`、`E2E_CBD_LMAX=9/39`）全部无效；只有每节点 `clEnqueueReadBuffer` 阻塞读回（全 CBD）才对。
10. **口径澄清**：lgdprobe（signed max）与 CBD（fabsf max）曾致误判；同运行内对齐后确认 CBD 开启时 lgd 读数完全正确（31.3428 / argmax 248069，与 CPU 一致）。
11. **提取路径全链核验**：LM head 在 CPU（output.weight buf=CPU，两 leg 一致）；result_norm 经 `CPU#result_norm#0` copy 槽；OpenCL `get_tensor` 全 CL_TRUE、`synchronize`=clFinish、CPU `cpy_tensor_async=NULL`、`tensor_copy` GPU→CPU 走阻塞 get——代码层同步语义无漏。
12. **二分实验重大勘误（收尾发现）**：上轮 `E2E_CBD_ONLY`/`LMAX` 系列**都没开 `E2E_CBD_PREFILL`**，只覆盖 decode 审计，而错误在 prefill ubatch1 就注入 ⇒ 那批 A/B 全部作废；用正确配置重跑「仅同步 result_norm（prefill+decode）」仍错（max=11.73），边界进一步收窄。
13. **阶段成果入库推送**：总档 §12.9、README Mesa 段落、.gitignore（build5/build_v86）；嵌套仓 271cf54 + 主仓 22e0e98 已推 GitHub。

| # | 问题 | 根因 | 解决 | 状态 |
|---|---|---|---|---|
| 1 | GET_ROWS 恒读零（l1/l2/l8+ 全线性层） | **sched 输入拷贝只注册一次**：idx 拷贝张量只在首个 gather split 注册，后续 29 个 split 不再拷贝；copy 张量 4 字节区域又被图尾 op 输出（off=8192，ssm_alpha 位型垃圾）复用 → 越界读 | pass-5 per-split 注册（移出 if） | ✅ 已修，实证有效 |
| 2 | 残留 L2 gather 仍读垃圾 | 写读同址、同 queue，形式因果违反 | 常量 idx（`LLAMA_RS_CONST_IDX=1`）：RS cache buffer 内持久化 [0] 张量，彻底脱离 sched 拷贝/区域复用生命周期 | ✅ 上线生效 |

## 六、本会话对整体项目的意义

1. **正确性质变**：全 GPU 卸载从「数值正确性未知」推进到「**计算已证明正确，只差最后一个读取假象**」。此前三轮战役（GPU bank 收口、融合排除、GET_ROWS 输出审计）都是在和「GPU 算错」这个错误假设搏斗；本会话用 7.7 万节点全量对账把这个假设连根拔掉，剩余问题的搜索空间从「整个后端」塌缩到「logits 读回一个环节」。
2. **两类系统性隐患定型**：sched 单次注册（上游同构）与 ggml-alloc 区域回收的复合伤害模式——这解释了为什么该 bug 在上游从未暴露（无跨后端 gather 密集图）、在我们 83-split MoE 乒乓结构下必然爆发；per-split 注册修复对上游也是有效贡献候选。
3. **常量 idx 是架构级规避**：不只是修 bug，而是把「跨后端小拷贝 + 区域复用」这一整类竞态从关键路径上移除，对后续 GPU bank / 更深 hybrid 图都成立。
4. **方法论资产**：CBD 逐节点审计 + 语义名配对 + 层误差热图已沉淀为可复用管线（`_probe/moe_probe/minicpm_e2e.cpp` + `/tmp/cbd_*.py`）；「探针三验、口径对齐、A/B 变量清单化」再添两条铁律（本轮 PREFILL 缺省是最新教训）。
5. **里程碑位置**：M2（整图单提交/全 GPU 真实 t/s）此前被正确性未知阻塞，现在只剩读取环节一关；Mesa 路线「GO → 数值正确 → 性能达标」三段中第二段实质完成。
