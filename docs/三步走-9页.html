到处都成立
只有两条普适杠杆：零拷贝直读 与 每 token 少读字节。其余全部环境相关。
第一步 · 同构2 / 9

prefill 的瓶颈，是「窗口内专家重拷贝次数」

在 5060 Ti 上用 fork 复刻 Strata，换来三条硬结论。

量出什么

ub 512 → 2048：pp 32–72 → 260–372，3.15×，零代码改动。

白捡什么

MTP 深草稿：n_max 4→8 仍 +73%，mean acc len 8.27。

证伪什么

16G 卡上专家热缓存：3 G 缓存 vs 40.9 G 专家，tg 34.7 → 15.9。

最大收获
同机直测 Strata 本体后「硬件墙」假说破产——差的是 fork 完成度，不是档位。
第二步 · 异构3 / 9

统一内存下，「内存分层」整类机制失去作用对象

把同一套机制移植到 ARM64 + Blackwell，得到三个边界判决。

判决一 · 空转

专家全常驻 ⇒ 没有拷贝要避免，分层 / 预取 / pinned 池整体失效。

判决二 · 带宽真相

273 GB/s 单池；零拷贝读 ≈225；拷贝引擎 H2D 50 / D2H 30。

判决三 · 真瓶颈

每步 ~500 个小 kernel 串行，有效带宽仅峰值 12%——不是带宽也不是算力。

结论反转
UMA 下唯一杠杆 = 每 token 少读字节；「先搬进设备内存再算」才是窄口。
第三步 · 端侧4 / 9

CUDA 上「改代码就生效」的假设，手机上不成立

后端能力塌缩，格式选择变成第一性约束。

Vulkan · 排除

原厂 e2e 0/6；Turnip 三药后也只有 5–11 t/s ⇒ 只留作驱动更新后复测。

OpenCL · 唯一可用

MoE 算子白名单只有 Q4_0 / Q8_0 / MXFP4，IQ 家族全缺席。

CPU · 格式自由

ggml-cpu 支持全部 GGML 类型（含自研 T42）⇒ 专家留给 CPU。

第一性约束
专家给 CPU、dense 给 OpenCL——双后端分工是唯一可行形状。
第三步 · 端侧5 / 9

35B-A3B 不是「小一号的 Flash」，换了三个结构

架构差异直接反转了优化优先级。

结构一 · 更稀疏

256 选 8 + 1 shared（Flash 是每层 512 专家）⇒ 热集覆盖率高 6.6×。

结构二 · 混合注意力

30 层 DeltaNet + 10 层全注意力 ⇒ KV 仅 10.9 KB/token（64K 只要 0.65 GiB）。

结构三 · 无投机层

无 MTP、无 PLE ⇒ 投机这条路关闭，形状固定 M = 1。

优先级反转
每 token dense 85% / MoE 12%——Flash 在 DGX 上的杠杆表不能搬。
第三步 · 端侧6 / 9

从内核白名单反推：GPU 上最小只能到 4.25 bpw

这个约束决定了「谁上 GPU、谁留 CPU」。

白名单

q1_0 q4_0 q4_1 q4_K q5_0 q5_1 q5_K q6_K q8_0 iq4_nl mxfp4

关键纠错

IQ 家族全缺席 ⇒ 上一版「重打包成 IQ2_S」是错的，GPU 上无路。

代价

2.25 → 4.25 bpw，专家 274 → 518 MiB/token，体积接近翻倍。

所以
要保住 T42 的 2.25 bpw，专家必须留在 CPU——这不是性能选择，是格式约束。
第三步 · 端侧7 / 9

把 UFS 当虚拟内存用，但走 mmap 干净页语义

手机没有可用 swap（ZRAM 对已量化权重压缩比 ≈1）。

三层

L0 Adreno 匿名热集 · L1 CPU 常驻 · L2 UFS mmap 冷专家。

为什么手机端才成立

3 GiB 热集 ⇒ 91 个/层 = 35.5% 覆盖；同样预算 Flash 只有 5.4%。

红线

单专家 4K 页 216 × 100 µs = 21.6 ms ⇒ 绝不能靠页故障。

调度四件套
热度表 · per-layer 填充 · 超集异步预读（读 top-32、只用 top-8） · 预算切分。
第三步 · 端侧8 / 9

要压的不是专家，是 dense 的 Q8_0

专家已经 2.25 bpw 到底，dense 还留着 8.5 bpw。

每 token 2304 MiB

attn/SSM 1222（53%）+ lm_head 600（26%）+ 专家 274（12%）。

A 案 · dense → Q4_0

省 635 MiB，零新内核（Q4_0 本就在白名单）。

B 案 · 词表 248K → 64K

省 445 MiB，需裁剪工具 + 采样映射。

净效果
2304 → 1224 MiB ⇒ 18.6 → 35 t/s（+88%）。专家再压到三元只省 2.6%，不做。
结论9 / 9

中等可行性：门控在「冷专家不 stall」，不在算力

两端的差距没有中间态好猜——这正是 P0/P1 要用低成本先量出来的。

乐观

17–20 t/s：热集覆盖 >35%，UFS 预读与 dense 计算完全重叠。

悲观

6–9 t/s：UFS 随机读藏不住，每次冷专家命中 stall 一整步。

路线 P0 → P4

能力探测 → 双路骨架 → 专家分层 → T42 CPU 内核 → 上 35B。

下一步
P0 量能力、P1 用 lfm2.5-8b-a1b（3.05 GB）做 A3B 缩比代理验机制——成本最低、信息量最大。
