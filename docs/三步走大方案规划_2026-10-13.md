## 第三步：手机端侧（8 Gen5 至尊 + 16G + OpenCL/Vulkan）× Qwen3.6-35B-A3B —— 🔵 规划定档

**模型事实（GSQ hybrid，11.37 GiB）**
- 专家 T42 2.25bpw 8.56G + dense Q8_0 1.89G + BF16 词嵌入 0.95G
- 40 层 / 256 专家 top8+1shared / 30 DeltaNet + 10 attn / 词表 248,320 / 无 MTP / KV 10.9KB/token
- 每 token 读量 2304 MiB：**dense 占 85%**（attn 1222 + lm_head 600），专家仅 12%

**分层架构（16G 硬约束下的唯一解）**
```
L0  Adreno GPU 常驻：dense 1.89G + embd 0.95G + 专家热集 3~3.5G
L1  CPU 内存冷专家池（按预算换入换出）
L2  UFS mmap 冷专家 ~5.06G（映射不驻留，绝不依赖 4K 页故障：一次 21.6ms）
```

**调度四件套**：热度表（离线标定+在线 EMA）· per-layer 预算填充 · **超集异步预读**（读 top-32 用 top-8，attention 时间盖住下层专家 UFS 读）· 预算切分

**内核自研线（OpenCL 白名单缺口）**
- 现状：Adreno 830 上 mul_mat_id（MoE）全量化数值损坏 = 驱动级 bug；dense Q4 正常，正以 **dense loop**（host 侧专家循环）绕行中
- 结论：**dense loop 与量化类型解耦** ⇒ 任何新量化类型只要做出 dense GEMV，MoE 自动继承同一条路
  0. **Q4_K_M 先通（2026-10-13 调整后的第一优先）**：q4_K 本就在 OpenCL 白名单内、dense 内核现成、MoE 走 dense loop 直接继承 ⇒ **零自研代码先把「Q4_K_M + dense loop MoE」全链路打通**，作为后续一切自研类型的对照基线
  1. **Q2_K 自研**（复用 q4_K 超块骨架，2bit 解包，零 codebook，GEMV 2-3 天）
  2. **IQ2_XS 自研**（复用 iq4_nl 的 16 条目 codebook 机制 + 新增 2bit/scale 解包，3-5 天）
  3. 全部过 test-backend-ops 数值门（自研内核不免疫驱动 bug）；gate+up 融合砍 launch 数（每层 9 次调用 × ~32 层）

**架构差异登记（2026-10-13 增补：①②代理 Qwen3.8-Flash-Next ≠ ③目标 Qwen3.6-35B-A3B）**

| 维度 | Qwen3.8-Flash-Next（①②） | Qwen3.6-35B-A3B（③目标） | 规划影响 |
|---|---|---|---|
| 层构成 | 48 层 hybrid（DeltaNet+attn 比例待实读 config） | **40 层 = 30 DeltaNet + 10 attn（75% DeltaNet）** | DeltaNet 算子占比极高 ⇒ OpenCL 可用性/CPU fallback 成本是 35B 特有风险，须前置验证 |
| MoE 路由 | 512 专家 top-10 + 1shared | **256 专家 top-8 + 1shared** | 稀疏度 2.0% vs 3.1%；热度分布形态不同 ⇒ 35B 热度表要重新标定，不能搬 3.8 的 |
| 每 token 读量构成 | 专家主导（DGX 优化主战场） | **dense 85%（attn 1222 + lm_head 600 MiB）/ 专家仅 12%** | **优化主战场反转**：35B 抓 dense 降档 + 词表手术，不抓专家带宽 |
| MTP 投机 | 有（coupled + Q4_0 草稿 = 真实 +28.9%） | **无 MTP**（端侧投机已证伪负收益） | ①②的投机收益结构**不可外推**；35B decode 账 = 读量削减 + 分层调度 |
| PLE | 有 per_layer_token_embd（DGX 包 26.8G） | 无 PLE | PLE 相关经验不迁移（好消息：dense 读量无 per-layer embd 拖累） |
| 量化格式 | 标准 llama.cpp 家族（IQ3_S/IQ4_NL/Q4_K_M/Q8_0） | **GSQ hybrid：专家 T42 2.25bpw + dense Q8_0 + BF16 embd** | T42 不在任何 OpenCL 白名单 ⇒ **双内核线**（见下） |
| 词表 | 248,320 | 248,320 | 词表手术（64K 子集 −445MiB）两边通用，可在代理上缩比演练 |

**由此新增两条规划约束：**

1. **双内核线分开管理**：
   - **A 线（通用 GEMV，OpenCL/GPU）**：Q4_K_M 先通 → Q2_K → IQ2_XS —— 服务 dense 部分 + Ling 代理全链路 + 未来备选专家格式
   - **B 线（T42 专家，CPU）**：GSQ T42 2.25bpw 是 35B 专属格式，A 线只复用方法论不复用代码；P3 落地，若 T42 内核失败则 fallback = 专家转 IQ2_XS（A 线成果在此接上）
2. **代理验证矩阵（Ling3.0-tiny + Q4_K_M 线能验什么；tiny 官方规格已联网查证 2026-10-13）**：
   - tiny 规格（HF 官方 README）：7.9B 总参 / **1.3B 激活 MoE**；**128 路由专家 top-8 + 1 共享**（与 35B 的 256 专家 top-8+1shared **同为 top-8 细粒度 MoE**）；注意力 = **3:1 KDA+MLA 混合线性架构**（KDA 即 delta-rule 线性注意力，**DeltaNet 近亲**）；官方提供 BF16/FP8/INT4
   - ✅ 直接验：OpenCL dense Q4_K_M 全链路、dense loop MoE、数值门流程、热度表+超集预读+pin 34% 分层机制、UFS mmap 冷专家、P0 带宽探针、**delta-rule 线性注意力算子族真机可用性**（KDA 层，为 35B 的 30 层 DeltaNet 提供近亲先例）
   - ❌ 验不了：Qwen DeltaNet 精确变体（KDA≠GDN 逐层配置，只能证算子族可行，不能证等价）；T42 格式
   - ⚠️ 失真项：激活 1.3B vs 3B、专家 128 vs 256、总权 INT4 ~4.4G 热集覆盖仍近 100% ⇒ pin ~34% 预算模拟不变；35B 特有杠杆（dense Q8_0→Q4_0 −635MiB、词表 64K −445MiB）只能解析推演 + 词表手术缩比演练

**可行性评级：中等**
- 乐观 **17-20 t/s** / 悲观 6-9 t/s，差别只在门控条件：**冷专家命中不 stall**
- 输入参考：8 Gen5 至尊 + 16G 上 35B-A3B CPU 解码目测 20 出头（用户口径，未上机实测）；这是乐观 17-20 估计的来源锚点
- 热集覆盖仅 ~35.5% 是最大失真点 ⇒ 一切机制成败在"miss 后 UFS 读被 attention 算力藏住"

**落地路线（P0→P4）**
| 阶段 | 内容 | 判定物 |
|---|---|---|
| P0 | 真机实测：LPDDR 有效带宽 + UFS 4.x 读带宽 + OpenCL 白名单复核 + **DeltaNet 算子可用性调研**（小模型先例/CPU fallback 成本） | 带宽数字表（一切账的前提） |
| P1 | **代理定案**：**Ling3.0-tiny**（7.9B 总参/1.3B 激活 MoE，128 专家 top8+1shared，3:1 KDA+MLA；官方 BF16/FP8/INT4）。LFM2.5-8B-A1B 为备选对照（其方案文档保留） | **Q4_K_M 全链路先通**（白名单内 + dense loop，零自研）→ 再调 IQ2/Q2；热集 pin ~34% 模拟 35B 失真的要求不变；**llama.cpp 对 tiny 架构（bailing hybrid + KDA）的 GGUF 支持待 P1.0 核对** |
| P2 | 专家分层 + 调度四件套落地 | 冷专家 miss 不 stall 的流水线实测 |
| P3 | 自研内核：Q2_K → IQ2_XS + dense loop MoE | 数值门 + 带宽效率 vs iq4_nl 同级 |
| P4 | 35B-A3B 真身上机 | 17-20 或 6-9，定案 |

**风险登记**
| 风险 | 等级 | 对策 |
|---|---|---|
| mul_mat_id 驱动 bug 波及自研内核 | 高 | dense loop + 每类型过 G2 数值门 |
| 4K 页故障毁步 | 高 | 全部预读显式化（async read，禁 fault 路径） |
| 热集覆盖 35% 导致流水线断裂 | 中 | 超集预读 + per-layer 预算 + 热度表在线更新 |
| DeltaNet 30 层 OpenCL 无内核先例 | 中 | P1 代理先行验证算子可用性 |
| launch 开销（~290 次/步） | 低 | gate_up 融合 + 异步 enqueue |
